# IH_VNS_TL
## 1. Библиотека (де)сереализации JSON формата 
В проекте используется поплуряное решение 'nlohmann': https://github.com/nlohmann/json
Для его установки надо скачать выполнить команду ```sudo apt install nlohmann-json3-dev```. 
## 2. Сборка проекта 
Нужно выполнить следующие шаги:
1. ```mkdir build && cd build```
2. ```cmake ..```
3. ```make```

Если все прошло успешно - в корне репозитория появится исполняемый файл **tdtsp_solver**.

## 3. Запуск программы
Реализован удобный скрипт для запуска **run.sh**. Поэтому после сборки для запуска достаточно выполнить следущие шаги:
1. ```chmod +x run.sh``` -- при запуске в первый раз. 
2. Запустить скрипт
## 4. Аргументы программы 
Для запуска необходимо выполнить следующее: 
``` ./run.sh -s <loyalty> -a <amount> -i <IterBeforeStop> -t <time_limit> -f <json>```
Где:
1. @loyalty - допустимая погрешность относительно нынешнего глобального минимума, которая позволяет добавить решение в список "потенциально хороших". По умолчанию -- 0.05.
2. @amount - количество "потенциально хороших" решений, необходимое, что бы заврешить поиск в этой итерации и перейти к глубокому исследованию. По умолчанию -- 5
3. @IterBeforeStop - Количество итераций без улучшения необходимых для завершения программы. По умолчанию -- 150.
4. @time_limit - буквально временное ограничение на выполнение алгоритма в секундах. По умолчанию -- 60.
5. @json - файл из которого взять данные. По умолчанию -- vrp_problems/0.json.
Пример:
```./run.sh -s 0.01 -a 5 -i 150 -t 60 -f vrp_problems/0.json```
## 5. Замечания
1. Можно просто запустить как ```./run.sh```. Или без какого-нибудь из аргументов. На место отсутствующего аргумента будет поставлено значение по умолчанию.
2. Существует флаг ```-h```. При использовании выводит в cmd текстовую информацию об использовании. 

## 6. Запуск на искусственных данных

 -  Для генерации искусственных данных можно использовать скрипт **generate_problems.py**. Он генерирует сколько попросите задач. Пример использования:
```python3 generate_problems.py -n 10``` -- Сгенерирует 10 задач.
- Для запуска алгоритма на сгенерированных данных можно использовать скрипт **find_solution.py**. Он запустит алгоритм на всех или избранных задачах из папки **Generated_SPB_problems** и сохранит решения в папку **Generated_SPB_solutions**. Пример использования:
```python3 find_solution.py --ids 1 3 5 12``` -- Запустит алгоритм на задачах 1, 3, 5 и 12. 

- Для отрисовывания итоговых маршрутов есть скрипт **visualize_solution.py**. Он отрисует маршруты для всех или избранных задач из папки **Generated_SPB_solutions** и сохранит изображения в папку **maps-solutions**. Пример использования:
```python3 visualize_solution.py --ids 1 3 5 12``` -- Отрисует маршруты для задач 1, 3, 5 и 12.

## 7. Управление честностью распредления маршрутов

Алгоритм поддерживает балансировку длин маршрутов между агентами. Степень важности честности задаётся параметром `fairness`:

- `fairness = 0.0` - алгоритм полностью игнорирует балансировку и фокусируется только на минимизации общей длины маршрутов.
- `fairness = 1.0` - алгоритм максимально старается сбалансировать длины маршрутов между агентами, даже если это может привести к увеличению общей длины маршрутов.

- Важно подобрать оптимальное значение `fairness` для каждой конкретной задачи, так как слишком высокое значение может ухудшить общую эффективность решения, а слишком низкое - привести к неравномерному распределению нагрузки между агентами. Рекомендуется экспериментировать с различными значениями `fairness` для достижения наилучших результатов.

- По умолчанию установлено значение `fairness = 0.5`.

Параметр передаётся в алгоритм через аргумент командной строки `-r` или `--fairness`. Например:
```bash
./run.sh -s 0.025 -a 5 -i 300 -f vrp_problems/0.json -o solution.json -t 15 -r 0.5
```


## 8. Визуализация метрик качества решений

После выполнения алгоритма сохраняются несколько JSON-файлов с решениями на разных этапах (например, `generated_solution_1_BEFORE.json`, `generated_solution_1_AFTER.json` и т.д.). Для их анализа и построения графиков используется скрипт **visualize_metrics.py**. Он читает эти файлы, извлекает метрики качества решений и строит графики для сравнения различных этапов оптимизации.

```python3 visualize_metrics.py --ids <ID задачи>```

## 9. Пример полного цикла работы с искусственными данными
1. Генерация 10 задач:
```python3 generate_problems.py -n 10```
2. Запуск алгоритма на всех 10 задачах с важностью честности 0.5:
```python3 find_solution.py -a --fairness 0.5```
3. Визуализация маршрутов для всех 1, 3,5, 10:
```python3 visualize_solution.py --ids 1 3 5 10```
4. Визуализация метрик качества решений для задач 1, 3, 5, 10:
```python3 visualize_metrics.py --ids 1 3 5 10```

Все результаты будут сохранены в соответствующие папки:
- Задачи: `SPB_problems/Generates_SPB_problems/problems`
- Координаты для визуализации: `SPB_problems/Generates_SPB_problems/coords`
- Решения: `SPB_problems/Generated_SPB_solutions/solution_<ID>`
- Карты: `SPB_problems/maps_solutions_SPB/maps_<ID>`
- Графики: `SPB_problems/Generated_SPB_solutions/solution_<ID>/Graphics/`
